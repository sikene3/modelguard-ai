# Phase 10 local-readiness evidence boundary

This directory records only the version-controlled description of the Phase 10 code-only evidence.
No AWS response, GitHub response, Terraform plan or state, credential material, subscriber endpoint,
raw scanner output, vulnerability database, container archive, or generated runtime artifact belongs
here.

Local generated evidence remains ignored:

- `artifacts/security/sarif/`: sanitized scanner output;
- `artifacts/phase-07-evidence/build/`: local image metadata generated by the existing build helper;
- `artifacts/phase-10-evidence/trivy/`: local exact-image Trivy/CycloneDX output; and
- an operator-selected temporary path outside the repository for the
  `modelguard.runtime-contract-verification.v2` local-image-ID record.

The report at `reports/phase-10.md` records command results only after each gate executes. Following
the fail-closed Docker host reset, all three final repaired images were rebuilt with BuildKit, scanned
by exact immutable image ID, and accepted by the sealed local runtime verifier with AppArmor,
built-in seccomp, and genuine `no-new-privileges`. The complete local Compose smoke/demo/E2E matrix
also passed. Private generated evidence is sealed under the approved durable Phase 10 backup root and
is intentionally not copied into this repository.

Local image-ID evidence does not by itself set Terraform `runtime_contract_verified=true`; a future
authorized activation must supply a matching clean-source immutable-registry-digest record. Live ECS,
IAM, S3, SSM, CloudWatch, Logs, SNS, Firehose, OIDC, budget, CloudTrail, Terraform, and teardown
evidence remains absent and must not be inferred from local tests.
